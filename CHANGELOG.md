# Changelog

## Unreleased

- **Share Changes** and **Get Changes**: share your work with co-authors from the command palette or the status bar, without git commands. Share saves all your edits as one version (with an optional description, "Update" by default), gets your co-authors' versions from every remote, and sends the result to your own remote only, so co-authors on GitHub and GitLab can each keep their own copy. A status bar item shows versions to get and send. Build files can be added to `.gitignore` in one click, and a conflict stops the share and opens the file with both versions marked.
- **Invite Co-author**: invite someone to edit by their GitHub username. A project that is not on GitHub yet is first put in a new private repository under your account. Uses VS Code's GitHub sign-in.
- **Invite codes**: **Create Invite Code** and **Enter Invite Code** connect two co-authors who each keep a copy on GitHub or GitLab. Each side gives the other's per-invite key read-only access to its copy as a deploy key, and adds the other's copy as a read-only remote, so Share Changes still sends only to your own copy. An empty project starts from the co-author's copy. A project that is not online yet gets a private copy where its author already keeps projects, GitHub or GitLab, told from the remotes and Git and ssh settings on this computer; Overtex asks which only when nothing points either way. Keys stay in `.git/overtex` and are used only for that remote, with GitHub's and GitLab's host keys pinned. GitLab needs an access token with the `api` scope, kept in VS Code's secret storage.
- **Reference hover**: hovering over the key in `\ref`, `\eqref`, `\cref` and the like shows the number and page from the last build's `.aux` files, following `\include`d chapters, with the section's title for section labels and the equation rendered with MathJax for equation labels. Keys no `\label` defines, keys added since the last build, and keys defined more than once are pointed out. Turn it off with `overtex.refHover.enabled`.
- Tectonic builds now keep the `.aux` and other intermediate files (`--keep-intermediates`), so the reference hover shows numbers and pages with Tectonic too. Clean removes them, with the `.aux` files of `\include`d chapters.

## 0.8.1 (2026-11-11)

- Check Bibliography warns about retracted papers, expressions of concern, corrections and newer versions, using the Crossref and Retraction Watch notices doi.org already returns. A retraction shows as an error in the Problems panel, with the notice's DOI, date and a link to it.

## 0.8.0 (2026-11-11)

- A build that prints nothing for `overtex.build.stallTimeout` seconds (default 300), or keeps printing the same lines, is stopped, and the error says why instead of the build hanging until you cancel it.
- When a XeLaTeX, LuaLaTeX or Tectonic build fails on a pdfTeX-only command such as `\pdfoutput=1`, the error says so and suggests building with pdfLaTeX.
- `⌘`/`Ctrl`+click in the PDF now puts the cursor on the word you clicked, not at the start of its line. When a word appears more than once nearby, the text around it in the PDF picks the right one.

## 0.7.0 (2026-11-11)

- **Check Spelling and Grammar** now works with nothing to install: it checks English with [Harper](https://github.com/Automattic/harper), which runs inside Overtex, so the text never leaves your computer. Math, comments, citation and reference keys, code and commands are left out as before, and findings land on the right word in the source, with quick fixes. American, British, Australian, Canadian and Indian spelling follow the document's language. The new `overtex.grammar.engine` setting picks `harper` (the default), `languagetool` for other languages through a LanguageTool server as before, or `off`. The dictionary and disabled rules are shared. The extension grows by about 8 MB for Harper's checker.
- **Export PDF with Notes**: a new command saves `main-notes.pdf`, a copy of the built PDF with your open PDF notes as standard sticky notes that Acrobat, Preview, Zotero and other readers show and can reply to. The PDF is not rebuilt (only built when there is none yet), so the notes land where you pinned them; its bytes are kept and the notes are appended after them. Done notes are left out, as are notes on pages the PDF no longer has, and the message says how many. Encrypted PDFs are not supported.

## 0.6.0 (2026-11-10)

- **Notes on the text**: leave notes for co-authors on the text of `.tex` files with the gutter's **+**, a selection and **Add Note**, or **Comments: Add Comment**. Notes are threads with replies, resolve/reopen and delete, signed with `git config user.name` and an ISO date, and saved in `.overtex/notes.json` at the workspace folder's root so they are shared through any git host. A note keeps the text it is on and a little context, and follows that text through edits, pulls and checkouts (the nearest occurrence when the text repeats, or the edited sentence between the same context). Notes whose text is gone are listed as Orphaned in the new Notes view, where they can be attached to a selection or deleted. The notes file is written only by those actions, never by editing, and is left untouched when it cannot be read.
- **To-dos view**: `\todo{…}` and `\fixme{…}` commands get a gutter mark and are listed by file in a new To-dos view in the Overtex sidebar, with multi-line notes and `[options]` read; those in comments and inactive blocks are left out.
- **History**: a new History view in the Overtex sidebar keeps a snapshot of the sources and PDF after each successful build, and on **Save Snapshot**. Each snapshot lists the files it changed; a file can be compared with its current version or restored, and a snapshot can open its PDF or be marked up against the files now with latexdiff. Named snapshots are kept; unnamed ones past `overtex.history.maxSnapshots` (default 50) are removed. A file's content is stored once however many snapshots hold it, in VS Code's workspace storage, not the project folder. Figures are not kept.
- **Check Spelling and Grammar**: a new command checks the active `.tex` file with a LanguageTool server on your computer (`brew install languagetool`, then `brew services start languagetool`). Only the prose is sent as text; math, comments, citation keys, code and tables are left out, and the findings land on the right spot in the source. Quick fixes apply a suggestion, add a word to the dictionary or turn a rule off. The language comes from babel or polyglossia, in the file or the main file, and is American English when the document names none. Turkish is not supported, since LanguageTool has none. `overtex.grammar.checkOnSave` checks on each save.
- **Present slides**: the Exit button now shows for a few seconds when a slideshow starts and whenever the mouse moves, with an "Esc to exit" hint. It used to appear only when hovered, so it was hard to find.

## 0.5.0 (2026-11-10)

- **Export Review PDF**: a new command builds `main-review.pdf` for co-authors or reviewers. Pick what it shows: line numbers, your open PDF notes as margin notes, and the changes since a git commit or another `.tex` file, marked up with latexdiff. Each note goes beside the source line SyncTeX finds for it, in `\input` files too; a note inside a table goes above the table. Done notes are left out, and your sources are not changed.
- **Present slides**: the PDF preview's new ▭ button and **Present PDF as Slides** show one page at a time, fit to the preview on black, for Beamer talks. Arrow keys, Space, Page Up/Down, Home/End or a click move through the slides, and Esc goes back to the page you stopped on. A rebuild stays on the same slide, forward search shows the slide for the cursor's line. For a projector, move the preview to its own window first.

## 0.4.0 (2026-11-09)

- **Overtex profile**: `profile/Overtex.code-profile` is a VS Code profile to import with **Profiles: Import Profile…**, from the file or its GitHub URL. It installs Overtex into a separate profile with a quieter editor (no minimap, breadcrumbs, sticky scroll, tips or AI chat; wrapped lines; a slightly larger font) and leaves your other profiles alone. `node scripts/profile.mjs` regenerates it. See README, *A separate, uncluttered profile*.
- **PDF preview layout**: the preview stays in the split you drag it to, instead of moving back beside the editor when it comes forward, and opens there again after you close it. **Move PDF Preview to New Window** (also a button in its tab bar) puts it in its own window, for a second screen. After a window reload or restart it comes back with the same PDF, page and zoom.
- **Labels panel**: a new view in the Overtex sidebar lists the `\label`s in the workspace's `.tex` files by kind, with undefined references on top, how often each label is referenced, and a warning for duplicates. Go to any definition or reference, insert a `\ref` at the cursor, or rename a label across the files, closed ones included. Go to definition, find references and F2 rename now work on labels without TexLab too; when TexLab runs, it keeps handling those, for the files linked by `\input`.
- **Tables and figures**: dropping a `.csv`/`.tsv` file into a `.tex` file inserts a booktabs table, and dropping an image inserts a figure, each with a caption and a unique label to fill in. Images from outside the main file's folder are copied into `figures/`, and a missing `booktabs` or `graphicx` package is added to the main file's preamble. New commands **Insert Table from CSV** (also converts selected tab-separated text) and **Insert Figure** do the same from a file dialog.
- **Setting up TeX**: when **Check LaTeX Installation** finds nothing to build with, its **Set Up…** button lists the ways to get there, lightest first: switch to Tectonic or Docker if one is installed, install Tectonic (with Homebrew, `brew install tectonic` is typed into a terminal for you to run; otherwise the installation guide opens), or install a full TeX distribution. The pick also sets `overtex.latex.tool` in user settings. Nothing is downloaded or installed without you running it.
- The README and the Getting Started walkthrough mention the separate Overleaf Connect extension as an optional way to work on Overleaf projects. Overtex still does not need Overleaf and never connects to it.

## 0.3.0 (2026-11-09)

- **Papers panel**: an Overtex view in the activity bar lists what the workspace's `.bib` files hold, grouped into Cited and Not cited and sorted by year, author or title. Each paper can be cited at the cursor, opened as a PDF (from its `file` field, else `papers/<key>.pdf` beside the `.bib`), shown in the bibliography or opened on the web. arXiv papers can be downloaded to `papers/` on request. Add Paper takes a DOI, an arXiv ID or BibTeX from the clipboard. Add Citation, Check Bibliography and the PDF download are the only features that use the internet, and only when run.
- **PDF notes**: double-click a page in the preview to pin a note there. Clicking a pin edits or deletes the note, and the toolbar's ✎ button hides or shows them. Notes are saved in `<main>.overtex-notes.json` beside the main file, not in the PDF, so they survive builds and Clean and can be committed; Export for arXiv leaves them out. A file Overtex cannot read (a git conflict, say) is left untouched and reported instead of being overwritten. A note stays at its position on its page and does not follow the text when an edit moves it. The marked-up PDF from Compare Versions takes no notes.
- **PDF notes as a to-do list**: a note's editor has **Mark done** and **Reopen**. A done note keeps its place as a faded ✓ pin. The toolbar's note list button shows how many notes are open and opens a list of all notes in reading order: tick a note off there, click it to jump to its pin, or turn on **Hide done** to take done notes off the list and the pages. **Check Submission** lists the notes still open. Notes files from older versions stay readable, and a done state is kept in the same file (`doneAt`). As before, a note stays at its position on its page, so it can end up away from the text it was about.
- **Build with Tectonic or Docker**: `overtex.latex.tool` picks `latexmk` (the default), `tectonic` or `docker`. Tectonic needs no TeX distribution and always uses XeTeX; Export for arXiv and Check Submission are not available with it. Docker runs latexmk in `overtex.docker.image` (default `texlive/texlive:latest`) with the workspace folder mounted at its own path and the network off. Compare Versions builds with the chosen tool, and **Check LaTeX Installation** checks what that tool needs. `overtex.tectonic.path`, `overtex.docker.path` and `overtex.docker.image` are ignored in untrusted workspaces.
- **Compare Versions** command: picks an old version (a git commit touching the document's folder, or a `.tex` file) and a new one (the files on disk, a later commit, or another file), runs `latexdiff --flatten` on read-only copies, and builds the marked-up document with latexmk using the project's engine, figures and bibliography. The result opens in the preview and stays as `<main>-diff.pdf` beside the build output. Nothing is checked out and git state is not changed. Changes only in comments or the preamble build nothing. `overtex.latexdiff.path` sets the executable, and **Check LaTeX Installation** now lists latexdiff.
- **Check Bibliography** command: checks the `.bib` in the editor, or those the main file names, and lists in the Problems panel entries missing fields their type needs (`journal` for `@article`, `booktitle` for `@inproceedings`, …), DOIs that do not exist, resolve to a paper with a different title, or repeat another entry's, and arXiv preprints whose arXiv record names a published version (with the journal reference and DOI). Verified DOIs also suggest a missing `volume` or `pages`. DOIs are looked up on doi.org (Crossref and DataCite), arXiv IDs in one batched arXiv API request; lookups that fail are reported as unchecked rather than wrong, and the check can be cancelled. It uses the internet only when run.
- **Cite from Zotero** command: opens Zotero's picker through the Better BibTeX add-on, adds the picked references to the bibliography the main file names (or the workspace's `.bib`, or a new `refs.bib`) and inserts `\cite{…}` at the cursor. Citation keys stay the ones Zotero shows. A paper already in the bibliography (same key or DOI) reuses its entry, and a key taken by a different paper gets a new one. Projects using biblatex get biblatex fields, others BibTeX. Local attachment paths (`file`) are left out. It talks only to Zotero's local server, at `overtex.zotero.url`.

## 0.2.1 (2026-11-08)

- Math hover preview: hovering over inline or display math, or an `equation`, `align`, `gather`, `multline` or similar environment, shows it rendered with MathJax 4. Macros from `\newcommand`, `\renewcommand`, `\providecommand`, `\DeclareMathOperator` and `\def` in the file and the main file are applied; TeX errors are shown in place of the image. MathJax is bundled separately and loaded on the first hover. `overtex.mathPreview.enabled` and `overtex.mathPreview.scale` control it.
- Fixed the PDF preview's dark pages button doing nothing when VS Code could not save `overtex.viewer.colorScheme` (as happens after an update until the window is reloaded). The preview now flips anyway and offers to reload the window.

## 0.2.0 (2026-11-08)

- Editor highlights for LaTeX: `TODO`, `FIXME` and `XXX` comments and `\todo{…}` notes get a background and a scroll bar mark (color `overtex.todoBackground`), and text TeX skips, `\iffalse … \fi` and `comment` environments, is dimmed. `overtex.highlights.enabled` turns them off.
- Word count in the status bar: after each successful build, `texcount` counts the document with its `\input`/`\include` files. `overtex.wordCount.goal` shows progress toward a target (`1,234 / 5,000 words`); the tooltip splits text, headings and captions and shows the words added this session. **Count Words** runs it on demand; `overtex.wordCount.enabled` turns it off.
- Dark PDF preview: `overtex.viewer.colorScheme` (`light`, `dark`, or `auto` to follow the VS Code theme) draws pages as light text on dark gray, keeping the hue of colored text and links. Images are inverted as well. The preview's toolbar button and **Toggle Dark PDF Preview** switch it; only the preview changes, not the PDF.
- **Check Submission** command: builds the project and lists what conferences, journals and arXiv tend to reject: more pages than `overtex.submission.pageLimit`, the `draft` class option, undefined references and citations (`??`) and duplicate labels, bitmap (Type 3) fonts, and `\todo`/TODO/FIXME left in the text (TODO comments are listed separately, since arXiv publishes the source). With `overtex.submission.anonymous` on, it also points at author names, affiliations, `\thanks`, acknowledgments and `pdfauthor` for double-blind review. Findings appear in the Problems panel until the next build.
- **Export for arXiv** command: builds the project, then zips the files TeX read according to latexmk's recorder (sources, figures, local packages, the generated `.bbl`) as `<main>-arxiv.zip`, with comments stripped from `.tex` files (verbatim environments, `\verb` and `\url` are left alone) and `\pdfoutput=1` added for pdfLaTeX. Build files in `overtex.latex.outDir` are moved beside the main file. Warns about a biber `.bbl`, a missing `.bbl`, XeLaTeX/LuaLaTeX, and inputs outside the main file's folder.
- **Add Citation from DOI or arXiv** command: fetches the BibTeX record from doi.org (arXiv papers through their DataCite DOI), gives it a key like `vaswani2017attention`, appends it to the bibliography the main file names (or the workspace's `.bib`, or a new `refs.bib`) and inserts `\cite{key}` at the cursor. A DOI already in the bibliography reuses its entry. The input box is filled from the clipboard when it holds a DOI or arXiv ID.
- **Check LaTeX Installation** command: finds latexmk, the engine, synctex and TexLab with the same `PATH` lookup the build uses, spots TeX that is installed but not on VS Code's `PATH`, and gives install steps for macOS, Windows and Linux. Offered once on startup when latexmk is missing, and from build or SyncTeX errors caused by a missing program.
- **Getting Started** walkthrough on the Welcome page: install TeX, open or create a document, build, preview and SyncTeX, optional TexLab.
- Hovering a key in `\cite{...}` (and natbib/biblatex variants) shows the entry's title, authors, year and abstract from the workspace's `.bib` files. Like `\cite` completion, it is off while TexLab runs, which has its own citation hover.
- Fixed the PDF preview growing and shrinking without stopping in Fit width (or Fit page) mode when the page was just tall enough to need a scrollbar.
- **New LaTeX Document** command: starts a project from a template (Article, Thesis or Report with chapters in separate files, Beamer Presentation, Letter) in the open folder, or in a new subfolder when the files would overwrite something. With no folder open, a one-file template opens as an untitled document and the others ask for a folder.

## 0.1.0 (2026-11-07)

First release.

- Build with latexmk (pdfLaTeX, XeLaTeX, LuaLaTeX), automatic BibTeX/Biber passes, build on save, cancel.
- Errors and warnings from the TeX log in the Problems panel.
- Built-in PDF preview (PDF.js) that keeps its scroll position across rebuilds.
- SyncTeX forward search (editor → PDF) and inverse search (⌘/Ctrl+click in the PDF → editor).
- Main file detection: setting, `% !TEX root`, `\documentclass`, workspace search.
- Citation key completion from the workspace's `.bib` files.
- Workspace Trust: building and cleaning are disabled in untrusted workspaces.
- Detects a double build with LaTeX Workshop and offers to turn off one of the two.
- TexLab language server integration: live diagnostics while typing, completion for commands, environments, labels and citations, hover and go to definition. Optional; starts only in trusted workspaces and stays off when the TexLab extension is installed. Settings `overtex.texlab.enabled`, `overtex.texlab.path`, `overtex.texlab.chktex`.
- SyncTeX works with PDFs built by other tools (absolute input paths) and with projects opened through a symlinked path.
